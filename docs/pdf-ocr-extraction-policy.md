# PDF・OCR由来の生態情報の抽出方針

## 基本原則

OCRは候補生成にのみ使い、原PDFの該当種・該当ページを目視確認した客観的な生態事実だけを収録する。OCR本文をそのまま公開データへ流し込まない。

収録対象は、発生期、越冬態、化性、寄主、ハビタット、分布、灯火・糖蜜などへの飛来、吸蜜、フェロモン誘引、行動、観察された相対的な個体数である。

以下は収録しない。

- 筆者の美的評価や好み（「美しい」「上品」「シブい」「かっこよい」など）
- 筆者の感情（「幸福感」「至福」「うれしい」「楽しい」など）
- 採集者向けの激励、収集の助言、熟練度や珍品度の評価
- 個人的な採集談、思い出、コレクター間の慣習
- 根拠が示されない将来予測や新産地への期待
- 図版、分布図、採集例、隣接種など、段組みから混入した本文以外の文字列

客観文と主観文が同じ段落にある場合は文単位で分け、客観文だけを採用する。判読不能な文字は文脈から推測で補わず、原PDFで解決できなければ `exclude_unresolved_ocr` または `needs_review` とする。

## 監査台帳と再生成

PDF監査の結果は `data/source_audits/` の台帳に、種、原レコードID、PDFページ、冊子ページ、採否、承認済み本文、除外理由、確認日とともに記録する。

公開可能なのは `decision=include` かつ承認済み本文がある行だけである。再生成スクリプトは台帳から `normalized_data/general_notes.csv` を更新し、`public/general_notes.csv` は正規化データから同期する。台帳にない抽出結果、`needs_review`、出典ページのない行は公開しない。

この原則はすべてのPDF出典に適用する。現時点で台帳との完全一致を機械的に検証しているのは、下記の『日本の冬夜蛾』由来の生態83行・出現時期103種と、各出典別台帳で明記した範囲である。別PDFから生態情報を新規・再抽出するときは、その出典用の監査台帳と検証ゲートを追加してから公開する。台帳化していない他出典の既存行を、監査済みとみなしてはならない。

文字の自動補正は改行由来の空白除去など、意味を変えないレイアウト正規化に限る。「ビーク」から「ピーク」、「SC」から「5℃」のような文字訂正は自動推測せず、PDF監査で確定した承認本文に記録する。

全件走査では、欄見出し接頭辞、編集的な参照案内、既知の意味崩壊語、月表記の崩れを候補として
検出する。ただし、推論表現や相対的な個体数の記述は、それだけでOCR破損とは判定しない。
候補は種見出しから原PDFの該当欄まで追跡し、寄主欄、監査・編集上の説明、推論、客観的な生態を
分離して台帳へ記録する。原画像から安全に復元できない項目だけを削除または保留する。

`validate-normalized` は、出典を問わず全一般注記へOCR段組み空白、欄見出し混入、主観・収集者向け表現、旧注記型の検査を適用する。旧取込行の多くは公開CSVの `page` が空欄なので、ページ番号は各出典台帳の適用ゲートで検証し、既存行を一括で監査済みにはしない。品質検査語は通常の生物名や客観文を誤検出しないよう、たとえば「オトシブミ」中の文字列や「採集例は少ない」という観察文を主観・欄見出しとして扱わない。

## 『日本の野生植物』のプロフィール・識別情報

植物プロフィールもOCRを候補生成にだけ用い、原PDFの種見出し、本文、左右の冊子ページを照合した短い客観的要約だけを公開する。第1巻の本文範囲はPDF p.17–305のうち冊子 p.33–608、第2巻はPDF p.16–316のうち冊子 p.31–630とする。図版・索引・検索表だけの記述は種プロフィールとして取り込まない。

PDFは1画像に冊子2ページを含むため、左右を分割してOCRする。`page` にはPDFページ、`printed_page` には冊子ページを保存し、サイトの出典表示には確認済みの `printed_page` を使う。複数ページは `;` 区切りの既知証拠集合として重複なしで保持し、両列を位置対応配列とは扱わない。正確なPDF・冊子ページ対は監査台帳に保存する。冊子ページと対応しない既存PDFページが同じプロフィールに残る場合、サイトでは `p.300 / PDF p.150` のように両方を表示する。原本は次のハッシュで固定する。

- 第1巻 SHA-256: `bcdcd5ac593747d6d58321d4a696ec96fb963233541af2a4666c4a1fbd1d4fb1`
- 第2巻 SHA-256: `2d104638c72cbfc58f17ab38223bce3d7798f72abc2d14fa4495a3a7546f3b12`

類似種・近縁種との見分け方は、次をすべて満たす場合だけ収録する。

1. 対象種の種解説内、または対象種へ直接接続された2分類群の対照表にある。
2. 比較対象が明示されている。
3. 葉、花、果実、毛、サイズ、開花期など、識別に使える具体的な差が書かれている。
4. 原PDF画像で対象種、比較対象、形質、冊子ページを確認できる。
5. 不確実性や例外がある場合は、その限定を落とさず短く要約できる。

単に「似る」「近縁である」と述べるだけの文、多数の分類群を横断する一般検索表の断片、系統関係だけの説明、園芸・採集上の助言、希少性や美しさなど筆者の評価は収録しない。長い原文転載はせず、`similar_taxa` に比較対象、`distinguishing_features` に具体的形質の客観的要約を保存する。比較文が誤って `habitat` や `distribution` に入っている場合は、原PDFで本来の欄を確認して分離する。同じ植物の識別情報は完全性・識別・整合修正のいずれか1台帳だけを正本とし、複数台帳から同義文を自動結合しない。複数候補を統合する場合は原PDFで形質と主語を再確認した正本文へ置き換える。

監査の正本は `data/source_audits/japanese-wild-plants-source-scope-2026-07-12.json`、`japanese-wild-plants-profile-completeness-2026-07-12.csv`、`japanese-wild-plants-identification-2026-07-12.csv`、`japanese-wild-plants-profile-integrity-2026-07-12.csv`、`japanese-wild-plants-taxonomy-followup-2026-07-12.csv`、`japanese-wild-plants-name-integrity-2026-07-12.csv`、`japanese-wild-plants-ocr-token-verification-2026-07-12.csv` とする。専用適用スクリプトは `decision=include` かつPDF・冊子ページが揃う新規行と、変更前後を完全一致で固定した整合修正だけを `normalized_data/plant_profiles.csv` へ反映し、除外・未確認行を公開しない。名称台帳も、変更前の和名・学名・科名・和文属名・ラテン属名が一致する行だけを訂正する。

YListとの科・学名差はOCR誤りの証拠にしない。原PDFの種・属・科見出しを確認し、原本の刊行時分類や有効な併記名であれば維持する。1列に複数のラテン科名を連結せず、原見出しが `LEGUMINOSAE (FABACEAE)` のように代替名を併記する場合は、正規化欄にデータ規約上の1名を保存し、見出し全体を監査注記へ残す。OCR誤読・段組みによる隣接科の混入だけを訂正する。

既存プロフィールの品質監査では、見出し・学名・図版番号の混入、主観表現、推測だけの文、既知のOCR誤読、和文中の段組み空白を機械的に全件検出する。意味を変える修正は対象種の原PDF左右ページで本文境界と対象種欄全体を目視確認し、変更前値、変更後値、PDFページ、冊子ページを整合台帳へ保存する。同じ字形誤読が多数回生じても、代表原画像の置換対応だけでは公開修正の根拠にしない。代表対応は候補探索に限り、各公開対象欄を原PDFで個別に読み直して、別種本文、同じ欄の別のOCR誤り、比較情報の取りこぼしがないことまで確認する。`verification_method=original_pdf_full_field_visual_review` は、この欄全体確認を完了した行だけに付ける。

完全性台帳は未抽出候補を全件原画像確認した範囲、識別台帳は類似・近縁候補を全件原画像確認した範囲である。旧抽出由来の既存プロフィール全件を個別に原画像再読したことを意味しない。既存行については上記の異常検出に該当した欄だけを再確認し、未検出行を原画像確認済みとみなさない。

OCR候補CSVや改善版パーサーの出力に名前が存在するだけでは「収録済み」と判定しない。`already_covered` として除外する場合は、最終的な `normalized_data/plant_profiles.csv` に同じ出典・正名の客観プロフィールが存在することを適用処理で検証する。旧OCR名だけが存在する場合は、正名の監査行を採用し、旧名を削除対象として台帳に残す。

## 種・亜種の適用範囲

文献が亜種を明記しない二名法または種和名だけで記述している場合、その情報を基亜種だけの記録とは解釈しない。原典の種解説全体が種単位で、後年の分類変更を含めても同じ種概念を指すことを確認できた場合は、`taxon_scope=species_level_shared` として現行の該当亜種へ共有できる。

ただし、次の順序で判定し、現在の全亜種へ機械的に複製しない。

1. 原典の学名・和名、種解説見出し、産地、図版・索引の対応を確認する。
2. 原典刊行時の種概念と、後年分離・統合された現行亜種の対応を確認する。
3. 三名法、亜種和名、限定産地が明記されていれば、その範囲だけへ帰属させる。
4. 亜種未指定の種レベル記録は、原典の種概念に含まれる現行亜種だけへ共有する。
5. 当時の基亜種概念に含まれていた後年分離亜種は `historical_subspecies_concept_shared` とし、当時から別概念だった島嶼亜種などは除外する。
6. 対応を一意に解けない記録、疑問符付き記録、別亜種の情報である可能性が残る記録は `needs_review` とし公開しない。

共有・除外の双方を監査台帳へ残し、原典の情報を名義亜種へ便宜的に寄せない。種レベルの既存IDがある場合は、原則としてそのIDに保持し、表示側が現行亜種との関係を解決する。
