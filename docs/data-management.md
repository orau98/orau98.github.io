# データ管理ポリシー

本リポジトリで扱う CSV や生成物が肥大化してきたため、今後の統制方針を以下のように整理しました。

## 正規化データを唯一のソースにする

- `normalized_data/*.csv` を編集の出発点（ソース・オブ・トゥルース）と位置づけます。
- `public/*.csv` はビルド処理や検証スクリプトの成果物として扱い、必要に応じて `npm run sync:public-insects`（CSV同期）や `npm run build:data-lite`（軽量JSON）で再生成します。
- 手動編集時は、`normalized_data` を更新 → 検証スクリプトを実行 → `public`／`dist` へ反映、という手順に統一します。
- 現在のデータ構造と安全な改善順序は `docs/data-structure.md` に整理します。

## 生成物と一次データの扱い

- `dist/` は GitHub Actions がデプロイ時に生成するビルド成果物で、Git 管理外（`.gitignore`）です。
- `public/assets/data-lite/*.json` や `reports/` の生成物、`cache/` などの再生成可能ファイルは `.gitignore` に追加し、新規成果物が Git に堆積しないようにしました。
- 解析途中の CSV やメモは `tmp/` ではなく、用途が固まったら `archive/public-archive/legacy-data/` などに移してラベル付けします。

## PDF・OCR由来の生態情報

- OCRは候補生成にだけ使い、原PDFを種・ページ単位で確認した客観的事実だけを収録します。
- 筆者の美的評価、感情、採集談、収集の助言、熟練度評価は生態情報へ収録しません。
- PDF監査の採否と承認本文は `data/source_audits/` の台帳に記録し、台帳にない抽出結果は公開しません。
- 詳細な採否基準、判読不能箇所の扱い、再生成手順は [PDF・OCR由来の生態情報の抽出方針](./pdf-ocr-extraction-policy.md) に従います。

## バックアップファイルの方針

- `*.bak.*` は最新 1 世代のみを残し、それ以前のバックアップは削除します。Git の履歴で復元できるため、バックアップの乱立を避けます。
- スクリプト実行時にバックアップが生成される場合は、`public/archive/` など保管場所を一箇所にまとめます。

## ローカル環境での作業メモ

- `tmp/` はあくまでワークスペースとし、出力物はコミットしません。必要な中間ファイルはドキュメント化して別ディレクトリに整理します。
- `build_logs.txt` やスクリーンショット等の一次資料は、用途が終わり次第削除するか、必要なら `docs/` にまとめて残します。

上記ポリシーに沿って維持管理することで、巨大な生成物や使い捨てファイルがリポジトリ内に溜まることを防ぎ、今後のデータメンテナンスを容易にします。
