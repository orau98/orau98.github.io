# CSVデータ品質 監査と正規化 — 修正内容と提案

生成: 2026-07-02 / ツール: `scripts/audit-csv-quality.mjs`（全量監査・依存パッケージ不要）
判定基準はサイト表示ロジック（`scripts/lib/dataLiteBuilders.mjs` = メタページ生成と同基準）と
YList（`normalized_data/ylist-lite.json`, サイトの権威的分類データ）を再利用。

`insects.csv` / `hostplants.csv` / `general_notes.csv` / `plant_profiles.csv` を全量走査し、
6カテゴリ（表記ゆれ・重複・無効植物名・科名不整合・非植物キー・参照整合性）で分類。
その上で **表示不変（サイト出力を変えない）かつ高信頼の決定的修正のみ** を自動適用し、
判断を要する残件は本レポートに提案としてまとめた。修正候補の妥当性は多エージェント検証で確認済み。

## 1. 適用した修正（hostplants.csv / public・normalized_data 両方 = 各449セル）

CRLF・クォート等の書式を保ったまま、該当セルのみを置換（行数16,795は不変）。

| 種別 | 件数 | 内容 |
| --- | --- | --- |
| `family_align_ylist` | 389 | 科名をYList権威値へ整列（例 ガマズミ: レンプクソウ科→ガマズミ科、クズ: ブナ科→マメ科、ヒサカキ: サカキ科→モッコク科、旧カエデ科→ムクロジ科 等）。**サイトは元々YListで科名を上書き表示するため表示不変**、生データの不整合のみ解消。 |
| `name_paren_canonicalize` | 37 | 植物名の括弧注記を除去（例「カマツカ（ウシコロシ）」→「カマツカ」「フヨウ (Hibiscus mutabilis)」→「フヨウ」）。**`normalizePlantNameLite`が元々除去してキー化しているため表示不変**。 |
| `name_descriptive_strip` | 17 | 説明的接頭辞/接尾辞を除去（「栽培ブドウ」→「ブドウ」「スギナと思われる」→「スギナ」等）。従来はサイトから欠落していた食草リンクを復元。 |
| `family_verified_override` | 6 | 多エージェント検証済みの手動裁定（サクラ→バラ科、アカシア→マメ科、モッコク→モッコク科）。YList非収録のため権威値が引けない総称/単型を補正。 |

修正の全明細: `reports/csv-quality/applied_fixes.csv`
再適用の決定ファイル: `reports/csv-quality/fix-decisions.json`（`--fix`が参照）

## 2. 多エージェント検証（`csv-quality-verify` ワークフロー / 12エージェント）

判断を要する部分を独立エージェントで検証し、誤修正を排除した。

- **科名整列のhomonym走査**: YList整列対象93植物を走査し、**同名異物リスクの検出はゼロ**。389件の科名整列は全て分類学的に妥当と確認。
- **説明的正規化(Tier3)**: 10件を独立2名が検証し **10/10承認**（全て同一植物）。
- **曖昧な科名衝突(4件)**:
  - サクラ→**バラ科**、アカシア→**マメ科**、モッコク→**モッコク科**（いずれも単一科で確定 → 適用済み）
  - トモエウツギ→**要専門家**。「トモエソウ（オトギリソウ科）」のOCR誤読の可能性が高い（同一蛾種に別抽出で「トモエソウ」記録あり）。原典照合が必要 → **未修正**。
- **素朴なtypo提案の検証(8件)**: 監査ヒューリスティックの提案8件中 **4件が誤り** と判明。`--fix`はこれら素朴提案を適用しない設計のため実害なし。正しい科は下表（提案1）に反映。

検証の生データ: `reports/csv-quality/verification-result.json`

## 4. その他の残件（提案）

1. **無効植物名（41件）** — `reports/csv-quality/invalid_plant_names.csv`
   - 大半（約35件）は**ラテン学名のみの正当な記録**（例 `Molinia japonica`, `Carex sp`）。サイト基準（日本語を要求）で植物ページ化されないだけで、データとしては有効。和名マッピングによる拡充は将来課題。
   - 明確な異常: 「卵形幼虫はアカシ」（OCR断片）、「綿」（1文字、→ワタ？）は手修正候補。
2. **非植物キー（27件）** — `reports/csv-quality/non_plant_keys.csv`
   - 菌類・動物質・「枯れ葉/朽ち木/樹皮」等。既に植物一覧・メタページから除外済み（昆虫側の食性記録は保持）。
   - 未除外の疑わしい値: 「セミ科/ヒグラシ」（昆虫）、「とセイヨウネズ」「であり」「には少ない」（OCR断片）は除外セット追加を推奨。
3. **非標準の科名（43件）** — `reports/csv-quality/non_standard_families.csv`
   - YList-lite の科集合(172)外というだけで、多くは**正当な科**（キキョウ科・キジカクシ科・ヤマゴボウ科等）や**非植物ホストの科**（サルノコシカケ科・多孔菌科・セミ科）。
   - 真の異常は少数: 「，ナス科」「，イネ科」「，キク科」（先頭全角カンマ）、「キネ科」（→イネ科）、「以ヒヤシ科」（→ヤシ科）、「クリノキ科（推定）」等。これらは植物名側もOCR破損していることが多く、行単位の手修正が適切。
4. **完全重複行（6グループ）** — `reports/csv-quality/duplicate_exact_rows.csv`
   - 正規化で変異形が既存行と同一化した結果。サイトはビルド時に重複排除するため表示は正常。生データ整理として重複行の削除は可能だが、record_id・件数が変わるため本PRでは保留。
5. **昆虫-植物ペア重複（601）/ プロファイル重複（1007）** — 参考情報。サイトは Set と `normalizePlantProfileRows`（最良1件を採用）で重複排除済み。生データのスリム化は将来課題。
6. **残る表記ゆれ（2件）**: 「マルメロ？」（不確実マーカー）、「ヤナギ属 Salix / ヤナギ属Salix」（空白差）。判断保留。

## 5. 監査ツールの使い方（自動化）

```bash
node scripts/audit-csv-quality.mjs          # 全量監査（読み取り専用）: reports/csv-quality-audit.md 等を生成
node scripts/audit-csv-quality.mjs --fix    # 高信頼の決定的修正を適用（fix-decisions.json があれば反映）
```

`npm run audit:csv-quality` でも実行可能。CIや今後のデータ更新時に定期実行することで、
科名不整合・表記ゆれ・無効植物名の再発を継続的に検出できる。

回帰テスト `tests/csv-quality-regression.test.mjs` は、
既知障害（広告プレビューの「ページが見つかりません」＝無効な植物名）の再発防止と、
科名整合・参照整合・public/normalized_data 同期を固定する（依存パッケージ不要）。
あわせて `isValidPlantName` の「括弧の後半のみ」検出を全角括弧にも対応させた（`scripts/lib/dataLiteBuilders.mjs`・`scripts/generate-meta-pages.js`）。
